# ⬇️ DEEP FALL

**落ち続けろ。止まった時が終わり。**

主人公はひたすら落下する。地面に触れた瞬間にゲームオーバー。
だから、下へ抜ける道を落ちながら作り続けるしかない。

**依存ライブラリ・ビルド・アセットは一切なし。** HTML と JavaScript だけで動く。

```
git clone <this repo>
cd bomgame
# index.html をブラウザで開くだけ
```

ローカルサーバーで見たい場合：

```
python3 -m http.server 8000   # → http://localhost:8000
```

## 操作

| キー | 動作 |
|---|---|
| `←` `→` | 横移動 |
| `↓` | 急降下（深度は稼げるが判断の余裕が減る） |
| `Space` | 爆弾を真下に落とす（数は有限） |
| `P` / `Esc` | ポーズ |
| `M` / `N` | 音楽 / 効果音 |
| `R` | 演出を抑える（画面揺れ・全画面フラッシュ・色ずれを止める） |
| `I` | 構造確認モード（無敵。詰まった地点を記録する） |
| `T` | 早送り ×1 → ×2 → ×4 → ×8 |

スマホ・タブレットでは画面下にタッチボタンが出る（キーの凡例は隠れる）。
横持ちで画面が低い時は「縦にしてください」と案内してゲームを止める。
**実機での確認手順は [docs/MOBILE.md](docs/MOBILE.md)。**
タイトルの「📱 端末チェック」で、端末側の判定結果をそのままコピーして送れる。

プレイヤーの真下に伸びる**赤い点線が、今のままだとぶつかる場所**。
これを見ていれば、次に何を突破すべきかが常に分かる。

## 隙間の作り方（地層9種）

このゲームの語彙。深くなるほど種類が増えていく。

| 地層 | 見分け方 | 抜け方 |
|---|---|---|
| **穴** | 岩に穴が1つ | そのまま通す。狭い穴を抜けるとボーナス |
| **二又** | 穴が2つ | 広いほうが安全。狭いほうは次に繋げやすい位置 |
| **もろい岩** | 茶色でひび割れ | ぶつかれば砕ける。ただし落下速度が半減する |
| **岩とひびの混在** | 一部だけ茶色 | 茶色の帯を狙う |
| **横に動く穴** | 上辺が黄色く光る | 穴が左右に往復する。読んで合わせる |
| **開閉する穴** | 同上 | 位置は固定で幅が伸縮する。閉じ切りはしない |
| **二重の動く穴** | 同上 | 逆向きに動く穴が2つ。どちらを取るか |
| **ボタン** | 壁の赤いランプ | 全面岩。落ちながら触れると爆弾が落ちて穴が開く。**左右どちらの壁にもある** |
| **埋まった爆弾** | オレンジに光る岩 | 穴は狭い。自分の爆弾を当てると誘爆して大穴。連鎖ほど高得点 |

どれも詰まったら**自前の爆弾**で掘れる。

## 爆弾の残数

**腰のポーチから手で取り出す。**初期3個・最大9個で、💣 のアイテムを拾わない限り増えない。

画面右上に丸で残数が出る（点灯＝残り）。**0になると赤く点滅し、押しても空振りする。**
主人公の腰のポーチも残数に応じて膨らみが変わり、空だと色がくすむので、
HUD を見なくても手持ちの状況が分かる。

100m ごとに地層帯が変わり（表土 → 玄武岩 → 結晶層 → 熱層 → 氷結層 → 深淵）、
落下速度も層の間隔も上がっていく。

## ご褒美の間（200m ごと・底なし）

**400m から先は難易度カーブが飽和して、構造としては同じものの繰り返しになる。**
それだけだと深く潜る理由が無くなるので、**200m ごとに必ず「ご褒美の間」を置いた。**

その区間は**岩が1マスも無い**（＝そこでは絶対に死なない）。数層ぶん開けたままにして、
落ちながら息をつきつつ取りに行く。中身は6種で、**深さに終わりが無いので巡回する。**

| 節目 | 名前 | 開く | 中身 |
|---|---|---|---|
| 200m ごと① | **補給の間** | 3層 | 爆弾を満タンに ＋ 💣×2 ＋ 結晶3 |
| 200m ごと② | **宝物庫** | 3層 | 結晶12個が蛇行して並ぶ。連続で取ると倍率が上がる |
| 200m ごと③ | **遺物の間** | 3層 | 🛡 シールドと 🔥 爆風アップが確定で浮かぶ ＋ 結晶3 |
| 200m ごと④ | **追い風の間** | 3層 | スロー6秒 ＋ 爆弾+2 ＋ 結晶5 |
| **1000m ごと** | **大空洞** | 5層 | 上の全部盛り。爆弾満タン＋シールド＋結晶18個 |
| **10000m ごと** | **地核の間** | **10層** | **シールドが上限の3枚を超えて5枚になる**（アイテム拾いでは絶対に届かない枚数）＋ 爆風を最大まで ＋ 爆弾満タン ＋ 結晶40個 |

到達ボーナスは節目ごとに増える（200m で +500、400m で +1,000 …）。
**普通の節目は 4,000m で +10,000 に張り付いて止まる。** 素直に増やし続けると
20,000m 到達時点で累計が数百万点になり、スコアの意味と HUD の桁が壊れるため。

**代わりに 10000m ごとの「地核の間」だけは伸ばしている**（10,000m で +25,000、
20,000m で +50,000、40,000m 以降は +100,000）。深く潜り続けたことへの見返りは、
毎回の細かい上積みではなく、この節目に集めてある。

画面右上に**次の節目・その中身・残り距離**が常に出ているので、目標は常に「次の節目」。

### 上限突破について

シールドは通常 3枚が上限で、🛡 を拾ってもそれ以上は増えない。
**「地核の間」だけがこの上限を超えさせる**（5枚）。

- HUD には**桃色のひし形**で上限突破ぶんが出る。場所は最初から確保してあるので、
  持った瞬間に他の数値がずれることはない
- 主人公のまわりの環も、内側に足すのではなく**外側に桃色の環**が増える
  （枚数ぶん内側に足すと、主人公自身が環に埋もれて見えなくなった）
- 上限突破ぶんを持っている状態で 🛡 を拾っても**減らない**
  （`Math.min(3, 5+1)` で丸めていて、拾うと5枚→3枚に減る不具合があった）

生成にあたって守っていること：

- **ご褒美の間も普通の層として置く**（全マス空にするだけ）。層を飛ばして空間を作ると、
  その区間だけ到達可能性と可視性の不変条件の外に出てしまう
- **結晶の蛇行の幅は、その深度で横に動ける距離から決める。** 固定値にすると深部では
  結晶の列が自分より速く逃げて、1個も取れない飾りになる
- **確定で渡すアイテムは、入口から横移動が間に合う位置に置く。**
  届かない場所の「確定」は飾りと同じ
- 出口は縦坑の全幅になるが、**どの列に居るかは決まらない**ので `exitFree` は立てない
  （次の穴は両端から届く位置に限る）

## アイテム

💣 爆弾 +1 ／ 🔥 爆風アップ ／ 🌀 スロー（落下が一時的に遅くなる）／
💠 結晶（点数。続けて取ると倍率が最大5倍まで上がる）

拾った時は**結果の値**を出す（「爆風アップ」ではなく「爆風 3/6」）。
ラベルだけだと、増えた実感も今いくつなのかも分からない。

### 常設の状態表示（画面左上）

**持っているのに画面のどこにも無い＝プレイヤーには存在しないのと同じ。**
シールドで一度やった失敗なので、残りも同じ基準で常に出している。

| 行 | いつ出るか | 中身 |
|---|---|---|
| **爆風** | 常時 | `2/6`。最大になると枠が付く。**最大が何なのかを画面に書いておかないと「爆風 最大」と言われても伝わらない** |
| **スロー** | 効いている間だけ | 残り秒数とバー。**切れる直前は点滅する。**さらにスロー中は画面の縁が紫に振れる（数字だけだと効いている実感が無い） |
| **結晶** | 連続中だけ | `×3` と、切れるまでのバー |

HUD（上の帯）は幅が一杯で置く場所が無かったため、縦坑の中の空いている左上に描いている。
**表示に使う値は `Game#statusRows()` が組み立てて返し、描画はそれを読むだけ**にしてある。
canvas の中身はテストから読めないので、こうしておかないと「本当に出ているか」を
機械で確かめられない（実際の描画も、値を変えたら絵が変わることで検査している）。

### 🛡 シールド

**岩に触れても死なず、代わりに1枚消費して岩を突き破る。** 落ちるしかないこのゲームで、
唯一「読み違えた」をやり直せる手段。

- 持っている間は**着地予測線が赤ではなく青**になる。助かる状態かどうかが常に見える
- HUD の SHIELD 欄にひし形で残数が出る（拾いで最大3枚、
  10000m ごとの「地核の間」でのみ5枚）
- 発動すると時間が一瞬止まり、青い衝撃波と「シールド発動！」で明示される
- 発動直後は 0.7 秒の無敵。**厚い岩でまとめて複数枚消えることはない**

### いちばん重要な制約：届かない隙間を作らないこと

落下は止められない。だから**横移動が間に合わない位置に隙間を1つ置いただけで
理不尽死になる。** 生成側で必ず守っているのは次の3つ：

1. **直前の層の「出口の範囲」から横移動が間に合う位置にしか次の隙間を置かない。**
   出口が固定の層（穴・ボタン・誘爆）は範囲の端から端まで全部届く位置に限り、
   出口が自由な層（もろい岩・動く穴）は好きな場所で抜けられるので緩く取る。
   この使い分けを `layer.exitFree` で切り替えている（`js/world.js`）。
2. **動く穴はプレイヤーの横移動より速く逃げない。** 振幅から角速度の上限を逆算している。
   これを外すと、穴が見えているのに永久に追いつけない層ができる。
3. **ボタン層は、両側の壁にボタンを置く。** 片側だけだと反対側から来たときに届かない。
   そのうえで、近いほうの壁へ届く落差を「層を置く前に」確保する。

### 構造確認モード（無敵）

`I` キー、または URL に `?inspect=1`。`T` で最大8倍まで早送りできる。
単なる無敵ではなく、**本来なら死んでいた地点を全部記録する**のが目的。
1回目の死で止まると、その先の構造が永久に検査されないため。

これを入れて 900m まで通したところ、深部の難易度カーブが破綻していることが分かった。
層の間隔を「行数」で詰めていたので、落下速度が上がるにつれて層と層の間の時間が
1.09秒 → 0.32秒 まで潰れ、その間に横へ動けるのは 1.86 マスしかないのに
穴の幅は 1 マス、という状態になっていた（詰まり20件）。
難易度を行数ではなく**時間**で定義し直し（1.15秒 → 0.78秒）、穴の幅の下限を
2マスにしたところ、900m まで詰まり0件になった。

### 構造監査（`node test/audit.js`）

**このゲームには終わりが無い。** だから「最後まで大丈夫か」は次の3つで答える。

**1. 難易度カーブがどこで最終形になるか**

| 深度 | 落下速度 | 横移動速度 | 層間 | 層間 | 穴幅 | 層間に横断できる幅 |
|---|---|---|---|---|---|---|
| 0m | 330px/s | 320px/s | 9行 | 1.15秒 | 3マス | 6.6マス |
| 200m | 475px/s | 430px/s | 11行 | 0.90秒 | 2マス | 7.0マス |
| **400m 以降** | **620px/s** | **540px/s** | **12行** | **0.78秒** | **2マス** | **7.6マス** |

**400m で飽和し、そこから先は同じ構造の繰り返し。** つまり 400m 以降を検査すれば
「最後まで」を検査したことになる。

**2. 静的検査** — 深度 0〜200,000m の全層（約15,600層）を 0.1 秒で検査する。
描画も物理も通さず、生成器が不変条件を守っているかだけを見る。
**200m ごとのご褒美 999 個**についても、欠けが無いか・全マス空か・
結晶と確定アイテムが届く位置にあるかまで同時に見ている。
**10000m ごとの別格 19 個**が全部「地核の間」になっていること、
逆にそれ以外の節目に混ざっていないことも確認している。

**3. 実プレイ検査** — 無敵で 120 秒潜り（約1,600m / 130層）、
物理・当たり判定・カメラ・フレームレート・メモリまで込みで見る。

この「抜けられなかった層」の数は、**生成の公平さと同時に自動操縦の腕も測っている。**
130層のうち1〜3層を外すことは実際にあり（動く穴を2つ追う spinner が大半）、
生成に問題が無くてもそのぶん揺れる。そこで実プレイ側のしきい値は
**「明らかな崩壊」を捕まえる位置**（100層あたり5層未満）に置き、数字そのものは
毎回出して推移が見えるようにしてある。**生成そのものの厳しい検査は静的検査が担う。**

fps も「最低の1秒」では判定しない。CI や共用マシンでは GC やホスト側の取り合いで
1秒だけ落ちることがあり、それはゲームの問題ではない。見たいのは
「ずっと落ちていないか」なので**下位5%と平均**で見ている。

静的検査は実プレイの100倍の深度を一瞬で見られるが、生成器の自己申告しか分からない。
実プレイ検査は遅いが実際の挙動が見える。**両方やって初めて「最後まで」と言える。**

### 動作確認

`node test/smoke.js` は**隙間へ向かって操作する自動操縦を積んで実際に潜らせる。**
生成が理不尽でないことを、静的な検査ではなく実プレイで確かめるのが目的。

- 6回走らせて到達深度の最小・中央値を検査（最小60m / 中央値100m 以上）
- **地層9種それぞれについて、その型だけを並べた縦坑を12秒間、墜落せずに潜れるか**
- 動く穴がプレイヤーの横移動より速くないか
- シールドが発動するか／1枚だけ消費するか／HUDに出るか
- 岩に触れたら墜落するか／落とした爆弾が穴を開けるか
- **無敵モードで 900m 通し、抜けられなかった層が 100層あたり2層未満か**
- **200m ごとのご褒美が1つも欠けないか／そこが全マス空か／中身5種が巡回するか／
  結晶と確定アイテムが落ちながら届く位置にあるか**
- **10000m ごとが別格になるか／シールドが上限を超えるか／HUD に出るか／
  超えた状態で 🛡 を拾って減らないか**
- **爆風が常に出ているか／スローの残り時間が減って切れる直前に点滅するか／
  結晶の倍率が連続中だけ出るか／値を変えたら実際に絵が変わるか**
- **外部配信が壊れた時に閉じ込められないか** — 例外を投げる provider・永久に返事をしない
  provider を偽物として食わせ、どちらでも必ず結果画面に戻れるか
- **サイト内の宣伝として使えるか** — `promos` の中身が出るか／押すと行き先が開くか／
  `onClick` で計測できるか／「広告」ラベルが出続けるか
- **演出を抑える設定** — OS の `prefers-reduced-motion` を既定にできているか
  （実際に reduce の browser context を作って確かめる）／手動で切り替わって保存されるか／
  抑えた時に揺れと色ずれが 0 になり、フラッシュが弱まり、CSS の点滅と拡大が止まるか
- どの深度でも次の層がカメラに入っているか（層の間隔 ÷ 見えている範囲）
- 60fps 出ているか

この自動操縦は開発中に実バグを6件見つけた：
動く穴が速すぎる／ボタン層の落差確保が層の後ろに入っていて効いていない／
二又の片方が到達不能／誘爆層の穴が深度に関わらず1マス幅固定／
動く穴を「出口を自分で選べる層」として扱っていた／
スピナーの2つの穴がすれ違う瞬間に、開いて見えて直後に岩になる罠ができていた。

最後の1件は、単独の型だけを並べる通過試験を入れて初めて出た。
混在した縦坑では他の型に紛れて「たまたま死んだ」に見えていた。

さらに無敵の通し確認と構造監査を入れて、次が判明した。いずれも
浅いところだけ見ていては絶対に出ない種類の不具合：

- **深部の難易度カーブが破綻していた。** 層の間隔を行数で詰めていたので、
  落下が速くなるほど層間の時間が潰れ（1.09秒→0.32秒）、その間に横へ動けるのは
  1.86マスなのに穴の幅は1マスだった
- **落下だけ速くしていた。** 620px/s で落ちながら横は320px/s では、盤面を横断するのに
  画面1枚ぶん以上落ちる。横移動も深度で上げて比率を保つようにした
- **ボタン層の落差確保が、その層の「後ろ」の間隔まで広げていた。** 後続の層が画面外に出ていた
- **ボタンを押してから穴まで横断する時間が無かった。** 穴の位置を縦坑の中央に固定し、
  そこまで届く落差をボタンの高さとして計算するようにした
- **到達可能性を「実際の落差」ではなく「その深度の標準間隔」で測っていた。** 両者がズレると
  届かない位置に穴が置かれる
- **動く層に開けた穴が次のフレームで塞がっていた。** 動く層は毎フレーム盤面を作り直すので、
  爆風で開けた穴も上書きされていた。爆弾を撃ち込んでも何も起きない層があったことになる。
  通し確認では、無敵で突き抜けるために開けた穴も同じように塞がるため、同じ岩に毎フレーム
  当たり続けて**その層で足止めされ、以降の深度が検査されていなかった**（1層の詰まりが
  37件に化けて見えていた）。開けた穴は列を覚えておき、作り直しの後で塗り直すようにした
- **詰まりの件数が「岩に触れた回数」だった。** 知りたいのは「抜けられなかった層の数」なので、
  同じ層の中の接触をまとめて数えるようにした。回数で数えると、壁1枚が何十件にも見える

## スマホ（`node test/mobile.js`）

**実機を触る前に、機械で分かることは全部潰しておく。**
キーボードで動くことは smoke で確認できるが、**タッチのイベント配線が切れていても
smoke は全部通ってしまう。** そこで自動操縦の判断を
「本物のボタンへの pointer イベント」に変換し、タッチの経路だけで潜らせている。

5端末（iPhone SE / 13 / Pixel 7 / 横持ち / 320×568）について：

- 操作ボタンが出てキーの凡例が隠れるか
- **押す的が 44px 以上か**（Apple HIG も WCAG 2.5.5 も 44px を目安にしている）
- ボタンが重なっていないか／画面の外に出ていないか
- 横スクロールが出ないか／**縦もスクロールなしで全部入るか**
- HUD のラベルが全部見えるか

そのうえで iPhone 13 相当で：

- タイトルのボタンを**タップして**始められるか
- **タッチだけで 60m 以上潜れるか**（横移動ボタンの押下回数も数えて、配線が生きていることを確かめる）
- 急降下で落下が速くなるか／爆弾ボタンで残数が減って爆弾が出るか／左右に動くか
- **ボタンの外へ指が出た時に押したままにならないか**（張り付き）
- **タッチ操作で結晶を拾えるか**
- 端末サイズで 50fps 以上出るか

### これで見つかった不具合

- **スマホでキーの凡例が出たままだった。** `@media (hover:none) and (pointer:coarse)` の
  ブロックが `#legend{display:flex}` の**前**にあり、同じ詳細度なので後に書いた
  ほうが勝っていた。狭い画面で縦を食うだけの害だった
- **横持ちだと下が見えなかった。** 低い横画面には縦坑が入らない
  （盤面 520px 幅 → 555px の高さ、画面の高さは 342px）。
  縮めるのではなく「縦にしてください」と案内し、覆っている間はゲームを止めるようにした。
  縦に戻しても自動では再開しない（持ち替えている最中に動き出すと、その一瞬で死ぬ）

### 端末チェック画面

タイトルの「📱 端末チェック」または `?device=1`。実機テストで一番困るのは
**「何が起きたかを持ち帰れないこと」**なので、この画面がその役目を持つ。

- 自動判定（画面サイズ・押す的の寸法・はみ出し・HUD・保存・**その端末での fps 実測**）
- 実機でしか分からない9項目に、その場で ○ / × を付けられる
- **「📋 結果をコピー」で全部テキストになる。**そのまま貼れば報告になる

## 演出を抑える（`R`）

このゲームは**画面揺れ・全画面フラッシュ・RGBずれ**を使っている。
これは演出の好みの問題ではなく、**人によっては本当に遊べなくなる**
（前庭系の症状・光感受性）。そのため逃げ道を用意してある。

- **OS の「視差を減らす」設定（`prefers-reduced-motion`）を既定として尊重する。**
  入っていれば最初から抑えた状態で始まる。OS 側の変更にもその場で追従する
- **`R` キーで手動でも切り替えられる。** OS 設定を変えられない環境（共用端末など）でも
  自分で選べるようにするため。手動で選んだらそちらが優先され、次回も保存される
- 検査用に `?reduce=1` / `?reduce=0` でも指定できる

抑えた時に何が変わるか：

| | 通常 | 抑えた時 |
|---|---|---|
| 画面揺れ | 爆発で最大26px | **0**（揺らさない） |
| RGBずれ | 最大5px | **0**（文字と岩の輪郭が二重に見えるので出さない） |
| 全画面フラッシュ | 最大1.0 | **0.22 まで**（消さずに弱める。消すと「何が起きたか」の手がかりも消える） |
| 破片の量 | そのまま | **35%**（画面全体のチラつきが減るだけで楽になる） |
| 弾む/点滅する UI | バナー・トースト・低残弾の点滅 | **淡いフェードと固定色**（動きと点滅だけを止め、色と配置は変えない） |

**レイアウトは変えない。** そこまで変えると、抑えた人だけ別の画面を見ることになる。

実装は `BM.a11y`（`js/const.js`）に集約し、CSS 側は `html.reduce-motion` の1クラスだけを見る。
メディアクエリと手動切替の二重管理にすると、片方だけ効いている状態が生まれる。

## CI（`.github/workflows/test.yml`）

push と PR で **構造監査 → 動作確認 → 同梱** を実ブラウザで走らせる。

- **監査を先に走らせる。** 生成の不変条件（0〜200,000m の静的検査）が落ちているなら、
  実プレイを待つ意味がない
- 落ちた時のスクリーンショットを artifact に残す
- **`dist/` がソースと一致しているかも確かめる。** ズレたまま公開すると、
  遊べる版とソースが別物になる（`node tools/bundle.js` の結果は決定的）

自動化した理由は単純で、**開発中に smoke が見つけた不具合が5件あり、
どれも目で見ただけでは分からないものだった**（結晶が届かない／上限突破ぶんを
持って 🛡 を拾うと減る／ご褒美の欠け／動く層の穴が塞がる／詰まりの数え方）。

## 配布用 ZIP（`npm run pack`）

ゲーム配信サイトへのアップロード用。

```
npm run pack        →  dist/deep-fall.zip   （55.8 KB）
npm run pack:test   →  展開して実際に遊べるかまで確認する
```

中身は2つだけ。

```
index.html   ゲーム本体。これ1つで完結している（175 KB）
README.txt   遊び方・操作・サイトに載せる人向けの説明
```

**`index.html` を ZIP の先頭に置いてある。** 多くの配信サイトはここを見るので、
そのままアップロードできる。外部通信も依存も無いので、置けばどこでも動く。

投稿サイト（GAMEYARD）の要件は **200MB まで / 5,000ファイル以内 / zip 直下に index.html**。
55.8 KB・2ファイルなので桁違いに余裕があるが、うっかりアセットを抱え込んだ時に
気付けるよう、この上限もテストの条件に書いてある。

投稿用のスクリーンショットは `node tools/shots.js` で `dist/press/` に4枚出る。
手で撮ると「たまたまその瞬間だった絵」になるので、見せたい場面を指定してある
（開発用の表示が写り込まないよう、撮る前に画面を掃除している）。
**投稿の手順と、貼り付ける文章は [docs/SUBMIT.md](docs/SUBMIT.md)。**

### zip コマンドを使わず Node だけで書いている理由

1. **依存を増やさない**（このリポジトリは依存ゼロを保っている）
2. **出力を毎回同じバイト列にできる。** 作った時刻を埋め込むと、中身が同じでも
   ZIP が変わってしまい、`dist/` をリポジトリに入れておけなくなる
   （CI の「dist がソースと一致しているか」が毎回落ちる）

### 確認していること

「アップロードしたら動かなかった」が一番まずいので、作れることだけでは終わらせない。

- **標準の `unzip` で開けるか**（自作の書き出しが規格に合っているか）
- `index.html` が ZIP の先頭にあるか
- **展開したものをブラウザで開いて、実際に潜れるか**（自動操縦で12秒）
- **外部へ一切通信していないか** — 1つでもあれば「どこでも動く」が崩れる
- 2回作って同じバイト列になるか

## ゲームオーバー時の枠（`js/ads.js`）

ゲームオーバーで 300×250 の枠を出す。**中身は2通りに使える。**

### (1) 自分のサイトの他のゲームを宣伝する【販売サイトならこちら】

```js
BM.ads.promos = [
  { title: 'ゲーム名', body: '説明', cta: '遊ぶ',
    url: '/games/xxx', accent: '#ffd23d', tag: 'おすすめ' }
];
BM.ads.onClick = function (promo) { /* 計測 */ };
```

外部の広告ネットワークと比べて：

- **審査がいらない**（AdSense の審査は落ちることもある）
- **同意管理（CMP）がいらない** — 第三者の追跡をしないので、EEA/UK 向けの同意取得が不要
- **広告ブロッカーで消えない** — 自分のサイトの自分のコンテンツなので
- **外部通信が増えない**（「依存なし・1ファイルで動く」性質を保てる）
- **そして収益が大きい。** 広告表示1回は数十銭だが、ゲームが1本売れれば数百円。
  販売サイトなら他のゲームへ送客するほうが桁違いに価値がある

### (2) 外部の広告配信に差し替える

```js
BM.ads.provider = {
  // container に配信タグを差し込み、表示が終わったら done() を呼ぶ
  fill: function (container, done) { /* ... */ }
};
```

ただし外部配信には次が要る。**技術より、この条件のほうが壁になる。**

- **審査を通したアカウント**（AdSense など）
- **自分が所有しているドメイン。** `*.github.io` のような他人のドメインでは登録できない
- **EEA/UK 向けの同意管理（CMP）**
- なお **AdMob はスマホアプリ用**（ネイティブSDK）なので、Web ページには入らない
- **Artifact では動かない。** セキュリティポリシーが外部スクリプトを全部止める

### どちらでも守っていること

- **「広告」ラベルを必ず出す。** 自社の宣伝でも隠さない（隠せば騙しになる）。
  文言は `BM.ads.label` で変えられるが、消す口は用意していない
- カウントダウンと、5秒後に押せるスキップ
- **頻度制御** — 既定では2回のゲームオーバーごと、かつ前回から45秒以上空ける
- 実在しない企業や商品を騙る広告は作っていない
- `?noads=1` または `BM.ads.enabled = false` で止まる。
  **有料のゲームとして売るなら、これで丸ごと外すのが正しい**（買った人に広告を見せない）

### 一番まずい壊れ方に備える

**外部スクリプトは落ちるもの**（広告ブロッカー・通信の失敗・SDK の読み込み失敗）。
その時に**結果画面へ戻れなくなる**のが、この枠で最悪の壊れ方。

実際、以前は `provider.fill()` の呼び出しが**スキップボタンとカウントダウンを組むより前**にあり、
外部スクリプトが例外を投げるとスキップは `disabled` のまま、カウントダウンも始まらず、
**リロードしか出口が無かった。**

いまは：

1. **出口を先に作る** — 何があってもスキップだけは効く
2. `provider` の呼び出しを **try/catch** で囲み、落ちたら自前の中身に差し替える
3. **無反応なら 8 秒で見切る**（`providerTimeoutMs`）

テストでは「例外を投げる provider」「永久に返事をしない provider」を偽物として食わせ、
**どちらでも必ず結果画面に戻れること**を確かめている。
