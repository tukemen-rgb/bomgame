# ⬇️ DEEP FALL

**落ち続けろ。止まった時が終わり。**

主人公はひたすら落下する。地面に触れた瞬間にゲームオーバー。
だから、下へ抜ける道を落ちながら作り続けるしかない。

**依存ライブラリ・ビルド・アセットは一切なし。** HTML と JavaScript だけで動く。

```
git clone <this repo>
cd bomgame
# index.html をブラウザで開くだけ
```

ローカルサーバーで見たい場合：

```
python3 -m http.server 8000   # → http://localhost:8000
```

## 操作

| キー | 動作 |
|---|---|
| `←` `→` | 横移動 |
| `↓` | 急降下（深度は稼げるが判断の余裕が減る） |
| `Space` | 爆弾を真下に落とす（数は有限） |
| `P` / `Esc` | ポーズ |
| `M` / `N` | 音楽 / 効果音 |
| `I` | 構造確認モード（無敵。詰まった地点を記録する） |
| `T` | 早送り ×1 → ×2 → ×4 → ×8 |

スマホ・タブレットでは画面下にタッチボタンが出る。

プレイヤーの真下に伸びる**赤い点線が、今のままだとぶつかる場所**。
これを見ていれば、次に何を突破すべきかが常に分かる。

## 隙間の作り方（地層9種）

このゲームの語彙。深くなるほど種類が増えていく。

| 地層 | 見分け方 | 抜け方 |
|---|---|---|
| **穴** | 岩に穴が1つ | そのまま通す。狭い穴を抜けるとボーナス |
| **二又** | 穴が2つ | 広いほうが安全。狭いほうは次に繋げやすい位置 |
| **もろい岩** | 茶色でひび割れ | ぶつかれば砕ける。ただし落下速度が半減する |
| **岩とひびの混在** | 一部だけ茶色 | 茶色の帯を狙う |
| **横に動く穴** | 上辺が黄色く光る | 穴が左右に往復する。読んで合わせる |
| **開閉する穴** | 同上 | 位置は固定で幅が伸縮する。閉じ切りはしない |
| **二重の動く穴** | 同上 | 逆向きに動く穴が2つ。どちらを取るか |
| **ボタン** | 壁の赤いランプ | 全面岩。落ちながら触れると爆弾が落ちて穴が開く。**左右どちらの壁にもある** |
| **埋まった爆弾** | オレンジに光る岩 | 穴は狭い。自分の爆弾を当てると誘爆して大穴。連鎖ほど高得点 |

どれも詰まったら**自前の爆弾**で掘れる。

## 爆弾の残数

**腰のポーチから手で取り出す。**初期3個・最大9個で、💣 のアイテムを拾わない限り増えない。

画面右上に丸で残数が出る（点灯＝残り）。**0になると赤く点滅し、押しても空振りする。**
主人公の腰のポーチも残数に応じて膨らみが変わり、空だと色がくすむので、
HUD を見なくても手持ちの状況が分かる。

100m ごとに地層帯が変わり（表土 → 玄武岩 → 結晶層 → 熱層 → 氷結層 → 深淵）、
落下速度も層の間隔も上がっていく。

## アイテム

💣 爆弾 +1 ／ 🔥 爆風アップ ／ 🌀 スロー（落下が一時的に遅くなる）

### 🛡 シールド

**岩に触れても死なず、代わりに1枚消費して岩を突き破る。** 落ちるしかないこのゲームで、
唯一「読み違えた」をやり直せる手段。

- 持っている間は**着地予測線が赤ではなく青**になる。助かる状態かどうかが常に見える
- HUD の SHIELD 欄にひし形で残数が出る（最大3枚）
- 発動すると時間が一瞬止まり、青い衝撃波と「シールド発動！」で明示される
- 発動直後は 0.7 秒の無敵。**厚い岩でまとめて複数枚消えることはない**

### いちばん重要な制約：届かない隙間を作らないこと

落下は止められない。だから**横移動が間に合わない位置に隙間を1つ置いただけで
理不尽死になる。** 生成側で必ず守っているのは次の3つ：

1. **直前の層の「出口の範囲」から横移動が間に合う位置にしか次の隙間を置かない。**
   出口が固定の層（穴・ボタン・誘爆）は範囲の端から端まで全部届く位置に限り、
   出口が自由な層（もろい岩・動く穴）は好きな場所で抜けられるので緩く取る。
   この使い分けを `layer.exitFree` で切り替えている（`js/world.js`）。
2. **動く穴はプレイヤーの横移動より速く逃げない。** 振幅から角速度の上限を逆算している。
   これを外すと、穴が見えているのに永久に追いつけない層ができる。
3. **ボタン層は、両側の壁にボタンを置く。** 片側だけだと反対側から来たときに届かない。
   そのうえで、近いほうの壁へ届く落差を「層を置く前に」確保する。

### 構造確認モード（無敵）

`I` キー、または URL に `?inspect=1`。`T` で最大8倍まで早送りできる。
単なる無敵ではなく、**本来なら死んでいた地点を全部記録する**のが目的。
1回目の死で止まると、その先の構造が永久に検査されないため。

これを入れて 900m まで通したところ、深部の難易度カーブが破綻していることが分かった。
層の間隔を「行数」で詰めていたので、落下速度が上がるにつれて層と層の間の時間が
1.09秒 → 0.32秒 まで潰れ、その間に横へ動けるのは 1.86 マスしかないのに
穴の幅は 1 マス、という状態になっていた（詰まり20件）。
難易度を行数ではなく**時間**で定義し直し（1.15秒 → 0.78秒）、穴の幅の下限を
2マスにしたところ、900m まで詰まり0件になった。

### 構造監査（`node test/audit.js`）

**このゲームには終わりが無い。** だから「最後まで大丈夫か」は次の3つで答える。

**1. 難易度カーブがどこで最終形になるか**

| 深度 | 落下速度 | 横移動速度 | 層間 | 層間 | 穴幅 | 層間に横断できる幅 |
|---|---|---|---|---|---|---|
| 0m | 330px/s | 320px/s | 9行 | 1.15秒 | 3マス | 6.6マス |
| 200m | 475px/s | 430px/s | 11行 | 0.90秒 | 2マス | 7.0マス |
| **400m 以降** | **620px/s** | **540px/s** | **12行** | **0.78秒** | **2マス** | **7.6マス** |

**400m で飽和し、そこから先は同じ構造の繰り返し。** つまり 400m 以降を検査すれば
「最後まで」を検査したことになる。

**2. 静的検査** — 深度 0〜200,000m の全層（約15,000層）を 0.1 秒で検査する。
描画も物理も通さず、生成器が不変条件を守っているかだけを見る。

**3. 実プレイ検査** — 無敵で 120 秒潜り（約1,600m / 130層）、
物理・当たり判定・カメラ・フレームレート・メモリまで込みで見る。

静的検査は実プレイの100倍の深度を一瞬で見られるが、生成器の自己申告しか分からない。
実プレイ検査は遅いが実際の挙動が見える。**両方やって初めて「最後まで」と言える。**

### 動作確認

`node test/smoke.js` は**隙間へ向かって操作する自動操縦を積んで実際に潜らせる。**
生成が理不尽でないことを、静的な検査ではなく実プレイで確かめるのが目的。

- 6回走らせて到達深度の最小・中央値を検査（最小60m / 中央値100m 以上）
- **地層9種それぞれについて、その型だけを並べた縦坑を12秒間、墜落せずに潜れるか**
- 動く穴がプレイヤーの横移動より速くないか
- シールドが発動するか／1枚だけ消費するか／HUDに出るか
- 岩に触れたら墜落するか／落とした爆弾が穴を開けるか
- **無敵モードで 900m 通し、本来なら死んでいた地点が 100層あたり2件未満か**
- どの深度でも次の層がカメラに入っているか（層の間隔 ÷ 見えている範囲）
- 60fps 出ているか

この自動操縦は開発中に実バグを6件見つけた：
動く穴が速すぎる／ボタン層の落差確保が層の後ろに入っていて効いていない／
二又の片方が到達不能／誘爆層の穴が深度に関わらず1マス幅固定／
動く穴を「出口を自分で選べる層」として扱っていた／
スピナーの2つの穴がすれ違う瞬間に、開いて見えて直後に岩になる罠ができていた。

最後の1件は、単独の型だけを並べる通過試験を入れて初めて出た。
混在した縦坑では他の型に紛れて「たまたま死んだ」に見えていた。

さらに無敵の通し確認と構造監査を入れて、次が判明した。いずれも
浅いところだけ見ていては絶対に出ない種類の不具合：

- **深部の難易度カーブが破綻していた。** 層の間隔を行数で詰めていたので、
  落下が速くなるほど層間の時間が潰れ（1.09秒→0.32秒）、その間に横へ動けるのは
  1.86マスなのに穴の幅は1マスだった
- **落下だけ速くしていた。** 620px/s で落ちながら横は320px/s では、盤面を横断するのに
  画面1枚ぶん以上落ちる。横移動も深度で上げて比率を保つようにした
- **ボタン層の落差確保が、その層の「後ろ」の間隔まで広げていた。** 後続の層が画面外に出ていた
- **ボタンを押してから穴まで横断する時間が無かった。** 穴の位置を縦坑の中央に固定し、
  そこまで届く落差をボタンの高さとして計算するようにした
- **到達可能性を「実際の落差」ではなく「その深度の標準間隔」で測っていた。** 両者がズレると
  届かない位置に穴が置かれる

## 広告（ゲームオーバー時）

ゲームオーバー時にインタースティシャル枠を出す。`js/ads.js`。

### 実配信について

**AdSense / AdMob などの実配信は、このままでは動かない。** 審査を通したアカウントと、
配信元ドメインからの外部スクリプト読み込みが必要で、このゲームは外部通信をしない前提で
作ってある（Artifact として公開した場合はセキュリティポリシーが外部スクリプトを全部止める）。

なので `js/ads.js` が実装しているのは **枠と出し方だけ**。

- 標準的な **300×250**（レクタングル大）の枠
- **「広告」ラベル** — 何が広告なのかを隠さない
- カウントダウンと、5秒後に押せるスキップ
- **頻度制御** — 既定では2回のゲームオーバーごと、かつ前回から45秒以上空ける。
  毎回出すと邪魔なだけになる
- 中身の既定値は**自社広告**（このゲーム自身の告知）。
  実在しない企業や商品を騙る広告は作っていない

### 実配信に差し替える

```js
BM.ads.provider = {
  // container に配信タグを差し込み、表示が終わったら done() を呼ぶ
  fill: function (container, done) { /* ... */ }
};
```

`provider` を入れれば自社広告の代わりにそれが使われる。
枠・ラベル・スキップ・頻度制御はそのまま流用できる。頻度は
`BM.ads.everyN` / `BM.ads.minGapMs` / `BM.ads.skipAfter` で変えられる。
`?noads=1` または `BM.ads.enabled = false` で止まる。

### テスト

広告のせいで結果画面が見られなくなるのが一番まずいので、そこを検査している。

- ゲームオーバーで枠が出るか／「広告」と明示されているか
- 出た直後はスキップできず、一定秒後に押せるようになるか
- **スキップすると必ず結果画面に戻るか**
- `everyN` の頻度制御が効いているか／`?noads=1` で止まるか
